01 · WHAT IS CENTRALIZED AAA?

AAA is the framework that controls who can access a network resource, what they are allowed to do, and records what they did.

THE THREE PILLARS

  • Authentication — Who are you?
  • Authorization — What are you allowed to do?
  • Accounting — What did you actually do?

WHY CENTRALIZE?

Without Central AAA:
  Switch A → local users
  Router B → local users
  Firewall C → local users
  → Inconsistent policy · Hard to audit · Password sprawl

With Central AAA:
  All devices → one AAA server
  → Single source of truth · Strong audit · Easy revoke

02 · KEY ACTORS & TERMINOLOGY

USER / SUPPLICANT

The human or device requesting access. Provides credentials (password, certificate, OTP, etc.).

NAS / NAD

Network Access Server (or Device). The switch, router, firewall, or wireless controller that enforces access. Talks to the AAA server.

AAA SERVER

Central policy engine. Validates credentials, returns authorization attributes, logs sessions. Examples: Cisco ISE, FreeRADIUS, Microsoft NPS, Aruba ClearPass.

03 · MAJOR AAA PROTOCOLS

Protocol Primary Use Transport Auth Separation Strength
RADIUS Network access (802.1X, VPN, Wi-Fi) UDP 1812/1813 Combined AuthZ Ubiquitous, extensible
TACACS+ Device admin (CLI / shell) TCP 49 Fully separated Command-level control
Diameter 3G/4G/5G, IMS, large scale TCP/SCTP 3868 Flexible Reliable, modern
LDAP / AD Identity store + simple auth TCP 389/636 Auth only Directory source

RADIUS → Best for network access control (NAC), 802.1X, VPN.

TACACS+ → Best for privileged device administration (who can run which CLI commands).

Diameter → Successor to RADIUS for mobile/carrier environments.

COMMON EAP METHODS

  • EAP-TLS — Certificate-based (strongest)
  • PEAP / MSCHAPv2 — Username + password inside TLS
  • EAP-TTLS — Tunneled TLS
  • EAP-FAST — Cisco flexible auth

WHAT THE SWITCH ENFORCES

After Access-Accept the NAS applies:

  • Dynamic VLAN assignment
  • Downloadable ACLs / dACL
  • URL redirection (guest / posture)
  • Session timeout / reauth
  • QoS / bandwidth limits

07 · ACCOUNTING, CoA & SESSION CONTROL

ACCOUNTING RECORDS

Accounting-Request (Start)
  • User-Name
  • NAS-IP-Address
  • Acct-Session-Id
  • Acct-Status-Type = Start
  • Calling-Station-Id (MAC)
  • Framed-IP-Address

Accounting-Request (Interim-Update)
  • Acct-Input-Octets / Output
  • Acct-Session-Time

Accounting-Request (Stop)
  • Acct-Terminate-Cause
  • Final counters

CHANGE OF AUTHORIZATION (CoA)

AAA server can push mid-session changes:

  • Re-assign VLAN
  • Apply new ACL
  • Force re-authentication
  • Disconnect (DM – Disconnect Message)

TYPICAL USE CASES

  • Posture assessment fails → quarantine VLAN
  • User moves from employee to contractor
  • Security incident → immediate disconnect
  • Guest session time expiry

09 · SECURITY & BEST PRACTICES

COMMON PITFALLS

  • Shared RADIUS secret too weak / reused
  • No message authenticator (UDP spoofing)
  • Accounting not enabled → blind sessions
  • Overly permissive default authorization
  • No CoA / Disconnect capability
  • Plain PAP instead of EAP-TLS / PEAP
  • Single AAA server (no high availability)

RECOMMENDED PRACTICES

  • Use strong, unique shared secrets
  • Prefer EAP-TLS or PEAP over PAP/CHAP
  • Enable Accounting + Interim updates
  • Deploy AAA servers in HA pairs
  • Use CoA for dynamic policy changes
  • Separate TACACS+ for device admin
  • Monitor failed auth & anomalous sessions
  • Certificate-based machine auth where possible
GOLDEN RULE: The NAS only enforces what the AAA server decides.
             Keep the policy engine central, the enforcement points
             simple, and every session fully accounted.
